# 船讯网船舶真实参数采集 — 技术报告

> 基于 Playwright + 船讯网 API 批量采集 309 艘船的静态物理参数
> 采集时间: 2026-06-09
> 最终覆盖率: 309 / 309 = 100%
> 输出文件: `output/shipxy_results.csv` + `output/ship_characteristics_db.csv`

---

## 1. 背景

### 1.1 问题

水路智能导航系统需要 309 艘船的静态物理参数（船长 / 船宽 / 吃水 / 限高 / 总吨 / 船型）做航道物理约束校验和 ADR-A\* 路径规划差异化约束。

### 1.2 数据缺口

原始 AIS 数据集只有 8 个字段（序号 / 船名 / 英文船名 / 航向 / 航速 / 纬度 / 经度 / 时间），**不含 MMSI / 船型 / 吃水 / 船长 / 船宽** 等静态属性。

### 1.3 推断数据的问题（采集前）

| 问题 | 表现 |
|---|---|
| 船型覆盖不全 | 10 种模板中 4 种（油轮 / 大型油轮 / 客船 / 大型货船）推断结果为 0 |
| 物理参数全靠模板 | 309 艘船的 `length/width/draft/tonnage` 全是 SHIP_TEMPLATES 估算值 |
| 仅 82 艘有船名佐证 | 227 艘纯靠最大航速推断船型，误判率高 |

例如：实际为液体散货的 `兴龙舟266`（53m × 10m）被推断为小型货船（80m × 12m），尺寸偏差 34%。

## 2. 验证过的 API

### 2.1 搜索接口（按船名查 MMSI）

| 项 | 值 |
|---|---|
| URL | `GET https://searchv4.shipxy.com/index.ashx?f=auto&kw={中文船名}` |
| 认证 | 无需登录，但需从 shipxy.com 域名下发起（带 Cookie）|
| 响应 | `{status:0, ship:[{m: MMSI, n: 英文名, t: 类型码, c: 呼号}], port:[]}` |
| 验证 | `东运628` → MMSI=413876838, DONG YUN 628 ✅ |

### 2.2 详情接口（按 MMSI 查参数）

| 项 | 值 |
|---|---|
| URL | `POST https://www.shipxy.com/ship/GetShip` |
| 参数 | `{mmsi: MMSI}` |
| 响应 | `{status:0, data:[{mmsi, cnname, name, type, length, width, draught, imo, ...}]}` |
| 单位 | `length / width / draught` 均为 **0.1 米**（590 = 59m）|
| 验证 | `东运628`: length=590(59m), width=130(13m) ✅ |

### 2.3 关键技术约束

**两个 API 均需浏览器上下文调用（CORS / Referer 限制）**，不能直接用 `requests`：

- `requests.post('http://www.shipxy.com/ship/GetShip')` → **403 / 401**
- 必须用 Playwright 打开 shipxy.com 后，通过 `page.evaluate()` + jQuery AJAX 发起

这也是为什么 `scripts/fetch_ship_info.py`（requests 版）实际上跑不通——它作为占位脚本保留，实际采集走 `scripts/fetch_shipxy_batch.py`（Playwright 版）。

## 3. 采集方案

### 3.1 整体流程

```
Step 1: 提取船名列表
  output/ship_characteristics_db.csv → 去重中文船名 → 309 个
  ↓
Step 2: Playwright 打开 shipxy.com
  启动 Chrome → 打开 shipxy.com → 等待 jQuery/config 就绪
  ↓
Step 3: 批量搜索（searchv4 API）
  309 艘船 × 搜索 → MMSI 列表
  ↓
Step 4: 同名船优选
  优先选 type 70-79（货船）→ 选 length 最大的（通常是主船）
  ↓
Step 5: 批量查详情（/ship/GetShip）
  309 艘船 × 详情 → 长宽吃水船型
  ↓
Step 6: 合并写入
  searchv4 搜索结果 + GetShip 详情 → shipxy_results.csv
  ↓
Step 7: 合并到主 DB
  shipxy_results.csv → ship_characteristics_db.csv
  真实值覆盖推断值，新增 mmsi/imo/data_source 列
  ↓
Step 8: 手动补全
  3 艘未命中的船从 shipxy.com 浏览器手动抓取
```

### 3.2 主脚本 `scripts/fetch_shipxy_batch.py`

**核心技术：Playwright + 浏览器内 jQuery AJAX**

```python
# 浏览器内 jQuery AJAX（绕过 CORS）
result = page.evaluate("""async () => {
    return new Promise((resolve) => {
        $.ajax({
            url: config.ship.searchServerUrl + '?f=auto&kw=' + encodeURIComponent('东运628'),
            type: 'GET',
            dataType: 'json',
            xhrFields: { withCredentials: true },
            success: function(r) { resolve({ok: true, data: r}); },
        });
    });
}""")
```

**限速与稳定性**：

| 参数 | 值 | 说明 |
|---|---|---|
| `SEARCH_DELAY` | 2.0 秒 | 搜索请求间隔 |
| `DETAIL_DELAY` | 2.0 秒 | 详情请求间隔 |
| `BATCH_SIZE` | 50 艘 | 每批暂停 |
| `BATCH_PAUSE` | 30 秒 | 批间长暂停，防封 IP |
| `MAX_DRAFT_M` | 25 米 | 吃水合理性上限（船讯网单位不统一，用此上限判断单位）|

**断点续采**：每艘完成即写 CSV，崩溃可从 `data_source='shipxy'` 的行继续。

### 3.3 同名船优选算法（`pick_best_match`）

船讯网搜索结果中同名船可能有多条（如 `宝利318` 搜出 10 条不同 MMSI）。选最优：

1. **优先选 type 70-79（货船）的候选**（最常见商业类型）
2. **次选 length 字段最大的候选**（主船通常最长）
3. **兜底返回第一条**

### 3.4 辅助脚本 `scripts/merge_shipxy_results.py`

- 读 `shipxy_results.csv` + 现有 `ship_characteristics_db.csv`
- 按 `ship_name` 匹配，用 shipxy 真实值覆盖推断值
- 支持 `--dry-run` 预览、`--backup` 备份原 CSV
- 输出覆盖率统计和分布报告

## 4. 字段映射

| shipxy 字段 | 主 DB 字段 | 转换 | 覆盖率 |
|---|---|---|---|
| `mmsi` | `mmsi` | 直接复制 | 100% |
| `imo` | `imo` | 直接复制 | 部分（多数国内船无 IMO）|
| `cnname` | `ship_name` | 直接复制 | 100% |
| `type` (AIS 码) | `ship_type` (中文) | AIS_TYPE_MAP 映射 | 100% |
| `length` | `length` | ÷10 → 米 | 100% |
| `width` | `width` | ÷10 → 米 | 100% |
| `draught` | `draft` | 单位自适应（mm/cm/0.1m 推断）| 66% (204/309) |
| `call_sign` | - | 不写入主 DB | - |
| `en_name` | - | 不写入主 DB | - |
| ~~`grossTonnage`~~ | ~~`tonnage`~~ | **API 不返回** | 0% |

### 4.1 吃水单位自适应

船讯网的 `draught` 字段**单位不统一**（不同船 / 不同时刻记录可能有 mm / cm / 0.1m 差异），采集脚本用以下策略推断：

```python
for divisor in [1000, 100, 10]:  # mm → m, cm → m, 0.1m → m
    draft_m = round(draught_raw / divisor, 1)
    if 0 < draft_m <= MAX_DRAFT_M:  # 合理性上限 25m
        record['draft_m'] = draft_m
        break
```

## 6. 集成到运行时

### 6.1 离线模式（当前默认，推荐）

- `output/ship_characteristics_db.csv` 已含 309 艘真实值，`data_source=shipxy`
- `ShipCharacteristicsManager._load_ship_db` 启动时一次性加载
- `get_ship_characteristics(ship_name)` 直接命中本地缓存，**不发任何网络请求**
- 性能：单次查询 < 1ms

### 6.2 在线查询降级链（防御性设计）

```
get_ship_characteristics(ship_name)
  ├─ 命中本地 ship_data（data_source in ('api', 'shipxy')）
  │   → 直接返回真实值
  ├─ 未命中且 api_enabled（设了 SHIPXY_API_KEY）
  │   → 调 GetShip 查询 → 写入本地 CSV
  └─ 完全没数据
      → 船名关键词推断 → 航速模式推断 → SHIP_TEMPLATES 兜底
```

`config.py` 中：

```python
SHIPXY_API_KEY = os.environ.get('SHIPXY_API_KEY', '')  # 留空 = 关闭在线查询
SHIPXY_API_ENABLED = bool(SHIPXY_API_KEY)
```

### 6.3 命名一致性说明

- 历史方案用 `data_source='api'`（占位）
- 实际采集用 `data_source='shipxy'`（数据源标识）
- `ship_navigator.py` 的判断条件为 `data.get('data_source') not in ('api', 'shipxy')`，**两种命名都不会触发在线查询**

## 7. 已知问题与限制

### 7.1 API 不返回吨位

- `GetShip` 接口**不返回** `grossTonnage` / `deadweight` / `netTonnage`
- 309 艘的 `tonnage` 字段**全部保留 SHIP_TEMPLATES 估算值**（15000 / 3000 / 200 / 300 / 100000 等）
- 改进方向：调 Equasis API 或购买 IHS Markit 数据

### 7.2 35% 船只缺吃水

- 105 艘（34%）的 `draft_m` 字段为空
- 原因：船讯网对这 105 艘本身没记录吃水（多半是 AIS 静态消息缺失）
- 影响：仍可做航道限高约束（用船宽/船长），但**不能做深水锚地约束**

### 7.3 3 艘特殊船需手动补全

- 兴龙舟266、南海神广州日报、广发证券号：自动化采集搜不到
- 原因：船名不在船讯网标准词库（"兴龙舟"是渡船/旅游船，"广州日报""广发证券号"是企业冠名宣传船）
- 解决：手动从 shipxy.com 浏览器抓取，已补全

### 7.4 船型码不统一

- 船讯网同时使用 AIS 标准码（30-99）和自定义码（100+）
- 100+ 自定义码更精细（如 100=集装箱船，114=原油船）
- AIS 码粗粒度（如 70-79 全部归"货船"）
- 主 DB 取 AIS 码映射，丢失了"原油船 vs 成品油船 vs LNG 船"的区分

## 8. 后续改进路径

### 8.1 短期（1-2 天）

1. **重跑 `fetch_shipxy_batch.py --resume`**：用最新船讯网数据刷新，捕获近期登记变更
2. **调整 AIS_TYPE_MAP**：把 100+ 自定义码的"集装箱船"等合并到主 DB 已有船型
3. **修补 draft 字段**：105 艘缺吃水的船，用船型 + 满载吃水经验值估算

### 8.2 中期（1 周）

1. **Equasis API 补吨位**：免费、覆盖 IMO 船舶，可批量补 `tonnage` 字段
2. **中国船级社 CCS 数据**：国内船免费，但需要爬虫
3. **增量更新脚本**：只采集新增/未命中的船，不全量重跑

### 8.3 长期（1 月+）

1. **API 监控**：船讯网接口可能变更，需定期验证 `searchv4` 和 `GetShip` 仍然可用
2. **多数据源融合**：船讯网 + Equasis + CCS，按字段最优源回填
3. **数据质量评估**：每个字段加 `confidence_score`（0-1），低分字段人工复核
