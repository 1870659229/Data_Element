## 3. HDBSCAN vs DBSCAN 对比（路径修复决策依据）

同一份输入（53,581 个特征节点），分别用 DBSCAN(eps=150m, min_samples=3) 和 HDBSCAN(min_samples=3) 聚类，对比 Task3 聚类结果和 Task4 拓扑网络质量。

| 指标 | DBSCAN | HDBSCAN | 胜者 |
|------|--------|---------|------|
| 拓扑节点 | 2,302 | **416** | HDBSCAN |
| 拓扑边 | 3,064 | 506 | HDBSCAN |
| 最大连通分量 | 100.0% | 99.5% | DBSCAN(微弱) |
| 水系验证通过率(<500m) | 45.4% | **54.3%** | HDBSCAN |
| 穿陆地边(>1km) | 37.1% | **25.1%** | HDBSCAN |
| 严重穿陆地(>2km) | 19.5% | **10.3%** | HDBSCAN |
| 路径可达率 | 100% | 100% | 平 |
| >10km 长边 | 14(0.5%) | 41(8.1%) | DBSCAN |
| 边长度中位数 | 339m | 1,261m | — |
| 耗时 | 111.88s | **72.68s** | HDBSCAN |

**HDBSCAN 全面优于 DBSCAN**：
1. 穿陆地边少 12 个百分点
2. 严重穿陆地边少近一半
3. 水系验证通过率高 9 个百分点
4. 网络更紧凑（416 vs 2,302 节点）
5. 速度快 1.5 倍

**DBSCAN 碎片化原因**：固定 eps=150m 在 4D 航向感知特征空间中，同一航道交汇点因航向差异被拆成多个小簇（5,328 个聚类 vs HDBSCAN 351 个）。

## 5. 水域面过滤第二轮修复（关键）

第一轮修复后，剩余 25% 穿陆地边多为合法绕岛边。原 `water-polygon-fix-plan.md` 提出的"直线采样 + 30% 比例"方案有两个根本性缺陷：

| 原计划假设 | 实际情况 |
|-----------|---------|
| "直线采样"能识别穿陆边 | **不能**——真实船舶轨迹沿水道绕行（折线），但 u-v 直线穿岛 |
| "30% 比例阈值"足够精确 | **不够**——窄航道边界采样误差就有 1-2 个陆地点，比例法会误判 |

**结果**：直接实施原计划会导致 40→405、40→71 等**合法绕岛边**被误删，A* 找不到直连路径，绕 38km 大圈。

### 5.1 真实实施路径（4 个关键修复）

#### 修复 1：waypoints 物理路径采样（`app.py:496-526`）

判断边是否合法穿岛，**沿真实轨迹采样**而不是 u-v 直线：

```python
edge_phys_path = None
if edge_waypoints and ((u, v) in edge_waypoints or (v, u) in edge_waypoints):
    pts = edge_waypoints.get((u, v)) or edge_waypoints.get((v, u))
    if pts and len(pts) >= 2:
        edge_phys_path = [(p['lat'], p['lon']) for p in pts]
```

**数据依据**：
- `output/edge_waypoints.csv` 包含 506 条边中的 470 条（92.9%）的真实航点
- 40→405 边 43 个 waypoints，沿水道绕岛 5.6km（**不是**直线 3.5km）
- 弯曲系数 1.58、最大垂线偏移 750m（典型内河航道绕岛几何）

#### 修复 2：连续 5+ 陆地点判定穿岛（`app.py:524-525`）

水域面边界本身有 50-100m 不确定度，**单点/2-3 点在陆上**很可能是窄航道边界不精确，**5+ 连续点**才确定为穿岛：

```python
# 连续5+个采样点在陆地 = 穿过岛屿（3-4个可能是窄航道边界不精确）
if max_consecutive_land >= 5:
    return False
```

**对比原计划**：原"30% 比例阈值"在 10 个采样点中需要 4+ 在陆上，等价于 2-3 个连续点——**误杀合法窄航道边**。

#### 修复 3：load_data 顺序调整（`app.py:153-172`）

`_filter_edges()` 在第 172 行调用，但 waypoints 加载原本在 192 行——**`_is_edge_near_waterway` 拿不到 waypoints**，退化到直线采样（旧的 bug 行为）。

**修复**：把 waypoints 加载提前到 `_filter_edges()` **之前**。

#### 修复 4：连通性恢复（`app.py:619-661`）

水域面过滤可能过度，删掉某些"虽穿陆但确为航道主通道"的边（如北江/绥江上游，OSM 水域面覆盖不全）。**修复**：过滤后**临时清除水域面数据**，对每条被过滤的边只检查水系线距离；如果该边是"通过水系线距离"但"未通过水域面"的边，再判断过滤后两端点是否不可达；不可达则恢复。

## 6. 关键经验

1. **直线采样 ≠ 真实路径采样**：拓扑边过滤不能用 u-v 直线，必须沿真实轨迹（waypoint）采样
2. **比例阈值 ≠ 连续性阈值**：水域面边界本身有 50-100m 不确定度，"连续 5+ 点"比"30% 比例"更鲁棒
3. **过滤后必须验证连通性**：水域面覆盖不全时（如北江/绥江上游），需"通过水系线距离但未通过水域面"的边可作为桥接边保留
4. **load 顺序有时序依赖**：waypoints 必须在 `_filter_edges` 之前加载，否则采样逻辑拿不到数据
5. **修复要分"层"**：snap 层只管端点，拓扑层管中段，渲染层管简化——**混在一起修效率低**
6. **数据验证不能假设**：水系数据"看起来存在"但实际不存在时，filter 应该 fail-loud（抛异常）而不是 fail-silent（返回 True）
7. **频次指标要有"白盒"定义**：HMM 命中 ≠ 真实密度 ≠ 频次概率，三者必须明确区分
8. **Task1-4 是耦合系统**：候选爆炸（Task2）→ 聚类噪声（Task3）→ 拓扑污染（Task4）→ 路径扭曲（渲染）。**单 Task 优化不能解决问题**
