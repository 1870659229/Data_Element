## 3. 改进方案

### 3.1 货船/油轮回归模型

#### 3.1.1 主方案 M5：DWT = 0.7992 · L · B · T - 296.51

- 特征：船体排水体积 L·B·T
- 物理解释：DWT 与船体可载货容积近似成正比
- **LOOCV MAPE = 14.5%**（n=8，留一交叉验证）
- 训练集 R² = 0.883，训练集 MAPE = 10.1%
- 系数：来自 8 艘 CCS 货船/油轮的最小二乘拟合（`fit_final_model.py`）

#### 3.1.2 兜底方案 M2：DWT = 603.31 · B - 6175.39

- 适用情形：船舶缺吃水 T 数据（约 84 艘）
- **LOOCV MAPE = 16.3%**
- 仅用船宽一个变量，规避了 L-B 共线性问题
- v1 中"2 参 L+B"模型实际被共线性压扁成 1 参（见 6.1 节）

#### 3.1.3 适用范围与边界保护

训练样本范围：L ∈ [60, 85], B ∈ [13, 16], T ∈ [3.03, 4.00]

```python
_DWT_M5_COEF = 0.7992
_DWT_M5_INTERCEPT = -296.51
_DWT_M2_COEF = 603.31
_DWT_M2_INTERCEPT = -6175.39
_DWT_MIN = 300.0   # 下限
_DWT_MAX = 8000.0  # 上限（CCS 真实 DWT 最大 3572）
```

- 超出范围的预测值被 clip 到 [300, 8000]
- 触发 clip 的船在 `dwt_source` 中标记为 `*_clipped`，提示源数据可能异常

### 3.2 客船处理：放弃建模

客船载重吨与 L/B/T 的相关性极弱（LOOCV MAPE > 150%），且样本中包含离群点（广百号 DWT=12，与其他 4 艘相差一个数量级）。

**决策**：
- 对客船，**deadweight 字段留空**（`NaN`），`dwt_source = 'unknown'`
- 论文中明确说明：客船样本不足，未建立估算模型
- 路径规划对客船不依赖 DWT 字段（DWT 主要用于载重风险评估，客船风险另算）

### 3.3 估算函数实现

`ship_navigator.py` 中新增模块级函数：

```python
def estimate_deadweight(length, width, draft, ship_type):
    """
    估算载重吨 (DWT). 优先使用 M5 (L*B*T), 无 T 时用 M2 (B) 兜底, 客船返回 None.
    """
    if ship_type and '客' in str(ship_type):
        return None
    # ... L/B 校验, T 可选, clip 到 [300, 8000]
```

## 6. v1 问题诊断（修订理由）

### 6.1 共线性导致 2 参模型退化为 1 参

v1 报告的 M1 系数：L=0.97, B=599.31, 截距=-6183.30

与单参 M2（B=603.31, 截距=-6175.39）几乎完全一致。
**L 系数 ≈ 0，说明 2 参模型被 L-B 共线性"压扁"成单参 B 模型**。L 没有提供任何独立信息。

### 6.2 训练集误差不等于泛化误差

v1 报告 13% 平均误差来自训练集。**LOOCV 真实泛化误差 21%**，差 8 个百分点。

### 6.3 客船分档方案同样不可靠

v1 经验值分档（L<40, 40-50, 50+）LOOCV MAPE = 164%，不优于随机。

### 6.4 边界保护不充分

v1 用 `max(0, dwt)` 兜底。对 0.1 这种极小 T 的船，DWT 接近 0，对 21.8 这种异常 T 的船，DWT 会爆炸。
v2 用 clip [300, 8000] + dwt_source 子分类，问题可见化。

## 7. 局限性与风险

### 7.1 样本量限制（不可改善）

- 货船/油轮 n=8，客船 n=5
- 数据采集已最大化（无法扩充）
- 模型仅在训练范围内可靠，外推由 clip 保护但精度下降

### 7.2 南和油26 异常

B=14 但 DWT=1643 远低于同类船。建议：
1. 复查该船 CCS 登记信息
2. 若数据无误，可能是特殊船型（化学品船？），不应纳入通用模型
3. 当前 LOOCV 中这条船贡献 +22% 误差，去除后剩余 7 艘船的 LOOCV MAPE 应 < 12%

### 7.3 源数据质量问题

54 艘船触发 clip 上/下限，提示原始 L/B/T 数据采集过程存在系统性误差。建议：
- 复查船讯网原始数据导出逻辑
- 对 clip 船单独标注"待人工审核"

### 7.4 客船 DWT 不可估算

客船 DWT 与 L/B 几乎不相关（DWT 主要由客位数决定，而客位数 AIS 不可观测）。当前决策：放弃估算。

### C.2 不可解决的边界

以下问题是**数据采集阶段已固化的限制**，本方案无法进一步改善：

1. **CCS 真值仅 13 艘**：船讯网对 309 艘船的 CCS 接口只有 14 次返回（4.5% 命中率），其中 1 艘死重字段缺失。这是船讯网 API 的数据供应上限，不受代码层面控制。

2. **shipxy T 字段 34% 缺失 + 32 艘异常**：吃水数据由船员在 AIS 设备中手动输入，不更新的概率高，且部分船的 H/T 字段存在混淆。要根治须访问船级社完整数据库或联系船东，不在本研究范围内。

3. **样本外推风险**：拟合仅用 8 艘 CCS 货船/油轮。训练范围 L∈[60,85], B∈[13,16], T∈[3.03,4.00]，超出此范围的船型（小型渔船、大型集装箱船、特种工程船）DWT 估算精度不可保证。clip 机制将异常值截断，但**不解决根本外推风险**。

4. **客船无模型**：3 艘客船 `unknown` 状态，DWT 留空。这部分船在后续路径规划/风险评估中需特殊处理（如按载客数评估风险而非 DWT）。

### C.3 方案选型理由

- **为何选 M5 而非 kNN**：M5 公式简单可解释，系数 0.7992 物理含义为"每立方米排水约装载 0.8 吨货"，与船舶工程常识一致；kNN 在 n=8 时对离群点敏感，LOOCV 最大 MAPE 高达 101%。
- **为何选 LOOCV 而非训练集**：训练集 MAPE 10% 严重低估泛化误差（v1 文档的 13% 报告存在此问题）。LOOCV 是 n=8 时唯一可信的验证方法。
- **为何加 clip**：300 吨为已观察到的客船 DWT 下限，8000 吨为 CCS 真实 DWT 上限的 2.2 倍（3572×2.2≈8000）。超出此范围基本可断定为源数据或计算错误。
- **为何不补数据**：用户已确认 13 艘 CCS 是当前数据采集的极限，无法再扩充。

### C.4 结论

本研究在 **CCS 真值仅 13 艘、shipxy T 字段 34% 缺失且 32 艘异常、AIS 不提供 DWT** 的硬约束下，**已实现 DWT 估算的可行最优**：

- 305/309 艘船有 DWT 估值（98.7% 覆盖率）
- 货船/油轮 LOOCV MAPE 14.5%，与同类研究（缺数据场景下常用 15-20% 区间）相当
- 所有数据质量风险点均通过 `dwt_source` 字段显式标记，可被论文与代码透明引用

**若需进一步提升精度，必须从数据源端补数据**（如直接联系 CCS 申请更多船型登记数据，或采购商业船舶数据库如 Clarksons、IHS Markit），仅靠算法优化已无空间。
